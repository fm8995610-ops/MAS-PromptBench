1Install

Clone and create the environment

One conda environment holds Python 3.11, vLLM, DSPy, the nine benchmark loaders and all four agent frameworks.

Don't skip the submodules. LangGraph, CrewAI and AutoGen are installed in editable mode from frameworks/, so the environment build fails without them.
bashInstall
# clone with the agent-framework submodules
git clone https://github.com/fm8995610-ops/MAS-PromptBench.git
cd MAS-PromptBench
git submodule update --init --recursive

# Python 3.11 + vLLM + DSPy + benchmark deps
conda env create -f environment.yml
conda activate mas-promptbench
pip install -U "dspy[optuna]>=3"   # GEPA ships with DSPy 3
2Connect a model

Point every agent at one endpoint

All agents call the same OpenAI-compatible chat API, set by three variables:

VLLM_BASE_URLthe endpoint URL, hosted or local
MODEL_IDthe model every agent uses
OPENAI_API_KEYonly if your provider needs a key
bashHosted API
# any OpenAI-compatible provider
export VLLM_BASE_URL=https://api.openai.com/v1
export MODEL_ID=<model-name>
export OPENAI_API_KEY=<your-key>
bashLocal vLLM
# one replica per visible GPU, on ports 8000, 8001, …
bash models/serve_qwen3_5_9b.sh

export VLLM_BASE_URL=http://localhost:8000/v1
export MODEL_ID=Qwen/Qwen3.5-9B
# no API key needed for a local endpoint

serve_qwen3_5_122b.shQwen3.5-122B-A10B-FP84 FP8-capable (TP=4)
3Run a baseline

Score the default prompts first

Every (topology, dataset) pair is one module. Run it with python -m from the repository root: the file-path form stops with ModuleNotFoundError.

python -m topologies.<topology>.[<framework>.]<dataset>.<framework>_<dataset>
--batch--limit N--offset K--only ID…--out PATH--out-dir DIR--help
Pass --out to keep predictions. Without it, GPQA, HotpotQA, MATH, LiveCodeBench and APPS batch runs only print scores. BFCL, SWE-Bench, ToolHop and API-Bank take --out-dir instead. The builder below fills in the right flags.
bashSingle agent · HotpotQA
# smoke demo: built-in example, no dataset download
python -m topologies.single.hotpotqa.langgraph_hotpotqa

# real batch on a 100-example slice
python -m topologies.single.hotpotqa.langgraph_hotpotqa \
  --batch --limit 100 \
  --out results/topologies_baseline/single_hotpotqa/predictions.jsonl
4Optimize prompts

Let GEPA or MIPRO rewrite the system prompts

Both optimizers run the real topology runners and re-score. The new prompts are kept only if they match or beat the baseline on validation.

GEPA · reflective prompt evolution: a reflection model reads traces and rewrites each agent's prompt.
MIPRO · searches over proposed instructions and few-shot examples.
Set the optimizer's own endpoints. The optimizers don't read VLLM_BASE_URL. Without the variables below, they fall back to built-in localhost defaults.
bashGEPA · Single · MATH
cd optimizers/gepa
export GEPA_TASK_ENDPOINTS=$VLLM_BASE_URL   # runs the agents
export GEPA_REFL_ENDPOINT=$VLLM_BASE_URL    # rewrites the prompts
export TASK_MODEL=$MODEL_ID REFL_MODEL=$MODEL_ID
export GEPA_EXCLUDE_REAL_EVAL_IDS=1         # never train on eval IDs

python -m real_runner_gepa.pilots.run_gepa_dataset \
  --dataset math --topology single \
  --train-size 25 --val-size 25 --max-full-evals 5 \
  --out results/gepa/single_math
bashMIPRO · Single · MATH
cd optimizers/mipro
export MIPRO_TASK_ENDPOINTS=$VLLM_BASE_URL  # runs the agents
export MIPRO_REFL_ENDPOINT=$VLLM_BASE_URL   # proposes instructions
export TASK_MODEL=$MODEL_ID REFL_MODEL=$MODEL_ID
export MIPRO_EXCLUDE_REAL_EVAL_IDS=1        # never train on eval IDs

python -m real_runner_mipro.pilots.run_mipro_dataset \
  --dataset math --topology single \
  --train-size 25 --val-size 25 \
  --num-candidates 3 --num-trials 3 \
  --out results/mipro/single_math

With several local replicas, list them all, comma-separated, in the task-endpoint variable. The code's defaults pair Qwen3.5-9B agents with Qwen3.5-122B for reflection.

Scores are fractions. Multiply delta by 100 to get percentage points, the unit used in the paper's tables. If the optimized prompts lose on validation, the run keeps the seed prompts ("selected_prompt_source": "baseline").

Scale Up

Launchers run one process per cell, so you can sweep a whole axis. Narrow any sweep with the environment variables shown.

bashSweeps
# baselines: topology, communication-protocol and team-size studies
DATASETS="math gpqa" bash scripts/run_topologies.sh
TOPOLOGIES="centralized" DATASETS="hotpotqa" FORMATS="freeform structured_soft" bash scripts/run_communications.sh
RVALUES="2 10" TOPOLOGIES="centralized" DATASETS="toolhop apibank" bash scripts/run_teamsizes.sh

# optimizers: one process per (dataset, topology)
DATASETS="math gpqa" TOPOLOGIES="single centralized" bash optimizers/gepa/run_gepa.sh
DATASETS="math gpqa" TOPOLOGIES="single centralized" bash optimizers/mipro/run_mipro.sh
topologies/
5 topologies × 9 datasets, the core runners
communications/
freeform to structured message formats
teamsizes/
teams of 2, 4, 8 and 10 agents
optimizers/
GEPA and MIPRO over the real runners
configs/prompts/
seed role prompts, read-only for optimizers
benchmarks/
frozen eval-ID manifests per dataset
models/
vLLM serve scripts for Qwen3.5
scripts/
sweep launchers for the three studies
